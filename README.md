# Silkbound: Сад после дождя

Играбельный прототип мобильного веб-платформера о паучихе Люме и физически
активной паутине. Реализован по трём документам репозитория: концепт-дизайну,
техническому GDD и спецификации первого playable-прототипа.

```bash
npm install
npm run dev      # локальная разработка
npm run build    # типизация + продакшн-сборка
npm run preview  # проверка собранной версии
npm test         # модульные тесты
```

Открывать в горизонтальной ориентации. Игра ставится как PWA и после первого
запуска работает офлайн.

---

## Что доказывает прототип

Три положения из раздела 1 спецификации:

1. **Пауком приятно управлять на сенсорном экране.** Плавающий стик,
   две основные кнопки, контекстные ножницы. Стик задаёт направление на
   экране, а не относительно героя, поэтому мир не переворачивается вместе
   с Люмой.
2. **Раскачивание ощущается естественно.** Активная нить удерживается жёстким
   проекционным ограничением маятника: касательная скорость сохраняется
   полностью, гасится только составляющая «наружу».
3. **Физические нити решают задачу.** Дверь у выхода открывается весом на
   напольной кнопке, и вес туда можно доставить минимум четырьмя способами.

## Комната

Одна комната из пяти зон, 4200 × 1500 логических единиц.

| Зона | Что проверяет |
| --- | --- |
| 1. Движение | пол → стена → потолок, обход углов, прыжок вверх на потолок |
| 2. Прыжок | coyote time, jump buffer, воздушное управление, автоприлипание |
| 3. Пропасть | прицеливание, выпуск нити, раскачивание, отпускание с импульсом |
| 4. Механизм | ящик, подвешенный груз, кнопка по массе, дверь |
| 5. Финал | выход, статистика забега, перезапуск |

Решения задачи с дверью: перетащить ящик; опустить груз на кнопку новой
нитью; построить направляющую сеть; подвесить груз над кнопкой и разрезать
удерживающую нить.

## Управление

**Сенсор.** Левая половина — плавающий стик (движение, воздушное управление,
раскачивание, подтягивание нити по вертикали). Справа — прыжок и паутина.
Экранные кнопки включаются автоматически на сенсорных устройствах; в
настройках их можно включить принудительно и вести стик мышью.
Короткое нажатие паутины — быстрый выстрел, удержание дольше 140 мс —
прицеливание с замедлением времени до 0.35. Кнопка ножниц появляется, только
когда рядом есть своя нить.

**Клавиатура.** `A`/`D` — движение, `W`/`S` — длина нити, `Space` — прыжок,
`E` или ПКМ — паутина, `Q` — разрезать, `R` — с контрольной точки,
`Esc` — пауза, `F1` — отладочная панель.

**Геймпад.** Левый стик, `A` — прыжок, `RT`/`X` — паутина, `B` — разрезать.

**Полноэкранный режим** переключается в настройках, раздел «Экран».

### Строительство постоянных нитей

Ключевой приём: выпустить нить, перебраться на поверхность и нажать паутину
ещё раз, стоя на ней. Свободный конец закрепится здесь, и получится
постоянная связь между двумя точками — то самое «прикрепить, переместиться,
закрепить второй конец» из раздела 19.1 GDD.

## Архитектура

```
src/
  app/          GameApp, GameConfig (все настраиваемые числа), палитра, HTML-оболочка
  core/         математика, шина событий, хранилище, отладочный слой
  game/
    spider/     датчик поверхности, контроллер, автомат состояний,
                контроллер паутины, процедурная отрисовка
    web/        граф, решатель, система, отрисовка нитей
    physics/    мир столкновений, материалы, единицы Matter
    level/      схема, загрузчик, валидатор
    objects/    ящик, груз, кнопка, дверь
    render/     фон, геометрия, объекты, частицы, прицел, текстуры
    camera/ audio/ input/ ui/ save/
  content/levels/prototype-room.json
tests/unit/
```

Несколько решений, о которых стоит знать заранее.

**Собственная геометрия вместо `Matter.Query`.** Паучихе нужна не пара
«столкнулись/нет», а точная ближайшая точка поверхности с нормалью — каждый
кадр, включая углы. Мир хранится как многоугольники, а ключевой запрос —
ближайшая точка границы. На выпуклом углу ближайшей становится сама вершина,
и нормаль поворачивается непрерывно: переход «пол → стена → потолок»
получается сам собой, без единой ветки кода на частный случай. Matter при
этом остаётся ответственным за твёрдые тела, столкновения и ящики.

**Скорость героя задаётся напрямую.** Для персонажа под управлением игрока
это единственный способ получить одинаковый отклик на камне, металле и
потолке: интегратор Matter иначе размазывает ускорение по-разному в
зависимости от накопленной скорости. Гравитация к герою применяется вручную —
отсюда предельная скорость падения и невесомость на стене.

**Паутина — позиционный решатель.** Стабилизированный Verlet с
проекционными ограничениями длины: не взрывается при большой жёсткости,
имеет предсказуемый бюджет кадра и явно ограничивает растяжение — ровно то,
что нужно системе натяжения и разрыва.

**Ни одного бинарного ассета.** Вся графика и весь звук создаются во время
выполнения: градиенты и шум — в canvas-текстуры, ноты нитей — суммой
затухающих обертонов, высота которой непрерывно зависит от длины и натяжения
нити. Первая загрузка мгновенна, офлайн-кэш весит меньше двух мегабайт.

## Соответствие спецификации

Реализовано: движение по любым поверхностям, обход углов, прыжок с
помощью игроку, автоприлипание с жёстким приземлением, выпуск и прицеливание
паутины с помощью и замедлением, раскачивание, подтягивание, разрезание,
крепление к статике и к динамическим телам, соединение двух точек,
натяжение с отложенным разрывом и оборванными концами, спящие сети, лимиты,
контрольные точки, зона падения и быстрый респаун, механизм с дверью,
камера с упреждением и тряской, отладочный слой `F1`–`F10`, настройки в
IndexedDB, PWA с офлайн-режимом, обработка сворачивания вкладки.

Осознанно вне прототипа (раздел 2.2 спецификации): сюжет, диалоги,
противники, вибрационная сеть, разные типы нитей, капли, ветер, карта, хаб,
коллекционные предметы.

### Отклонения от чисел ТЗ

Четыре решения расходятся с буквой ТЗ, и вот почему.

- **`referenceHeight`: 720 → 600.** При 720 единицах по высоте Люма на
  телефоне занимает меньше двадцати пикселей, и вся процедурная анимация ног
  пропадает. 600 сохраняет ощущение огромного мира и возвращает герою
  читаемый силуэт.
- **`maximumAttachmentForce`: 1600 → 12000.** В ТЗ это число записано «в
  единицах конкретного движка». В принятой здесь системе (масса × единиц/с²)
  груз массой 2.4 в поле 1750 весит 4200, и предел 1600 не дал бы нити
  удержать даже сюжетный груз. Смысл ограничения сохранён: это страховка от
  рывка при ошибке решателя, а не предел прочности — за него отвечает
  `breakStretchRatio`.
- **Модель звука нити: Карплус — Стронг → аддитивный синтез.** Петля
  обратной связи с линией задержки на низких нотах имела коэффициент выше
  единицы (усиление обратной связи вместе с резонансом фильтра) и вместо
  затухания раскачивалась в низкочастотный гул. Сумма затухающих обертонов
  звучит так же, но разогнаться не может по построению.
- **Критерий сна нити: порог по скорости → порог по смещению.** В
  позиционном решателе туго натянутая нить долго несёт затухающую стоячую
  волну: её мгновенная скорость периодически проскакивает любой разумный
  порог, хотя нить визуально неподвижна. Порог по смещению средней частицы
  за окно выражает требование «состояние не менялось заданное время» честнее.

## Тесты

`npm test` — 41 модульный тест: геометрия и непрерывность нормалей в углах,
создание нитей и лимиты, натяжение, отложенный разрыв, передача нагрузки
телу, сериализация графа, засыпание, автомат состояний, шина событий,
согласованность единиц Matter с гравитацией из конфигурации, валидация
комнаты.

Отладочные клавиши для ручной проверки: `F2` коллайдеры, `F3` нормали,
`F4` частицы, `F5` натяжение цветом, `F6` пауза физики, `F7` шаг,
`F8`/`F9` тестовые нити, `F10` очистить паутину.
